Quick Help

Pairs are between []. Each pair has field name + operator + field value. Connect multiple pairs with AND, OR and NOT, and group them using brackets. AND takes precedence over OR; two pairs without any operator between them are connected by AND. Example: [title*=test] AND ([facet=default] OR [facet=tiled]) AND NOT [flags:to revise].

A query without any [ searches for items whose title contains it: e.g. chronicle is the same as [title*=chronicle].

Each pair about pins matches items having any pin like that, whatever the part providing it: so [tag=odd] AND [year==1200] finds items having both a pin tag=odd and a pin year=1200.

Fields

  • t, title: item's title.
  • dsc, description: item's description.
  • facet, facetId: item's facet ID.
  • group, groupId: item's group ID.
  • sortKey: item's sort key.
  • flags: item's flags.
  • itemId: item's ID.
  • creatorId: item's creator.
  • userId: item's last user.
  • timeCreated, timeModified: item's creation and last modification time.
  • partId: part ID.
  • type, partType, partTypeId: part type ID.
  • role, roleId: part role ID.
  • n, name: pin's name.
  • v, value: pin's value.
  • time, timeIndexed: pin's indexing time.

Any other name is the name of a pin, matched against its value: e.g. [eid=x12]. Pin names are case-sensitive. To search a pin whose name is equal to a field (e.g. a pin named title), prefix it with @: [@title=Chronicon].

Operators

  • =: equal to.
  • <>: not equal to.
  • *=: contains.
  • ^=: starts with.
  • $=: ends with.
  • ?=: wildcards: ?=any single character, *=0-N characters.
  • ~=: regular expression (PostgreSQL syntax).
  • %=: fuzzy matching. The value can be followed by : and the minimum similarity threshold, from 0 to 1 (default 0.9): e.g. [title%=chronicon:0.4].
  • ==: equal (numeric).
  • !=: not equal (numeric).
  • <: less-than (numeric).
  • >: greater-than (numeric).
  • <=: less-than or equal (numeric).
  • >=: greater-than or equal (numeric).
  • : (flags): any the specified flags (comma-separated) must be present.
  • &: (flags): all the specified flags (comma-separated) must be present.
  • !: (flags): none of the specified flags (comma-separated) must be present.

Text matching is case-sensitive, and values are literal: e.g. % has no special meaning in [dsc*=100%]. Numeric operators consider only values which are numbers.

Flags are comma-separated, each specified either with its label or with its hexadecimal value: e.g. [flags:to revise,4].

Time fields accept only comparison operators (=, <>, ==, !=, <, <=, >, >=) with dates, e.g. [timeModified>=2024-05-01].

Value escapes: \[=[, \]=], \\=\, \HHHH=Unicode 16-bits character code. Any other backslash is kept as it is, so that regular expressions like \d+ can be written as such.
